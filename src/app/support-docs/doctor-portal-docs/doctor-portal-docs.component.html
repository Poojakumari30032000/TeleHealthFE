Doctor Portal User Manual

Medical Practice & Telehealth Platform

Support Documentation
1. Introduction

This user manual describes how doctors use the Doctor Portal within the medical practice and telehealth platform. It explains the key features available to doctors, including scheduling, patient management, treatments, prescriptions, orders, and secure messaging.

The portal is designed to give doctors a single place to manage their daily work across one or more clinics, while remaining tightly integrated with the global administration team and third- party pharmacy services.

1.1 Audience

This document is intended for licensed doctors who have been granted access to the Doctor Portal, and for internal teams who need to understand doctor-facing workflows (e.g., product, QA, and support).

1.2 Role in the System

In the overall system, the doctor works under the Global Admin for contractual and payment purposes, and operationally with one or more clinics. Doctor availability is defined globally and shared across all clinics, ensuring that a doctor can never be double-booked in two clinics at the same time.

Doctors can view and manage their own schedules, patients, treatments, prescriptions, medicine orders, and direct messages with patients and clinic staff. Clinics and patients cannot manually create appointments; only doctors can create or adjust appointment bookings.

2. Accessing the Doctor Portal

Each doctor receives their own login credentials to access the Doctor Portal. After signing in, the system directs the doctor to the main dashboard, which provides an overview of active patients, treatments, pending tasks, and key performance indicators.

3. Doctor Dashboard

The dashboard is the doctor’s home screen. It provides a quick snapshot of workload and activity, and shortcuts into detailed sections of the portal via the left-hand navigation menu.

Figure 1: Doctor Dashboard – overview cards, charts, and navigation menu.

Key elements of the dashboard include:

  • Summary cards showing counts of Active Patients, Active Treatments, Pending Prescription Uploads, and Pending Appointments.
  • Daily appointments table indicating the doctor’s upcoming schedule for the current day.
  • Charts for total patients and treatment types over a selectable date range.
  • A left-side navigation menu to access Scheduling (Calendar and Availability), My Patients, Treatments, Orders, Prescriptions, Messages, and other modules.
4. Scheduling

The Scheduling module allows doctors to manage their global availability and appointments across one or more clinics. Availability is defined once and shared with all clinics. When a time slot is booked in any clinic, it is automatically blocked for all others, ensuring the doctor is never double-booked.

4.1 Calendar View

The Calendar view displays all appointments for the doctor in a familiar calendar layout. Doctors can review their schedule by day, week, or another available time range, and they can manually create new appointments.

Figure 2: Scheduling – Calendar view with filters and Create Appointment action.

From the Calendar view, the doctor can:

  • See appointments by time and date, with the current day visually highlighted.
  • Switch between different views (e.g., week view) using the view selector.
  • Filter appointments by clinic and other criteria using the Filters panel.
  • Use the Create Appointment action to manually schedule new appointments with patients.

Appointment statuses may include Pending, Confirmed, Completed, Cancelled, and No-show, helping the doctor track the outcome of each booking.

4.2 Availability

The Availability view lists all configured availability blocks for the doctor. Each availability block defines a date or range, slot duration, and number of slots that can be booked within that period.

Figure 3: Scheduling – Availability configurations and Add Availability button.

From the Availability view, the doctor can:

  • Review existing availability entries, including title, provider, start date, slot count, and slot duration.
  • Create new availability blocks using the Add Availability button.
  • Determine how many appointment slots will be generated from a given availability configuration.

Once availability is defined, clinics can book the doctor within those slots. If one clinic books a time slot, that slot becomes unavailable to all other clinics automatically.

5. My Patients

The My Patients module displays a list of all patients assigned to the doctor. From here, the doctor can open individual patient records to review clinical history, treatments, prescriptions, and orders.

Figure 4: My Patients – list of patients assigned to the doctor.

The patient list typically includes:

  • Registration date and basic identification details (name, MRN, email, phone).
  • Counts of treatments, prescriptions, and medicine orders associated with each patient.
  • Clinic information indicating which clinic the patient is linked to for this doctor.
  • An action menu to open the full patient record and view more details.

Each patient also has a questionnaire completed during the Get Started flow. Doctors can view this questionnaire for clinical context, but cannot edit the responses.

6. Treatments

The Treatments module allows doctors to work with patients in the context of specific treatment types. Treatments are pre-defined in the system (e.g., Mental Health, Ketamine Therapy, Testosterone, etc.) and are selected by the patient during the Get Started flow.

Figure 5: Treatments – patient list organized by treatment records.

Key aspects of treatment management include:

  • A treatment record is created as soon as a patient completes the Get Started flow and selects a treatment type.
  • The doctor, before the appointment, has the patient's history and the details based on the intake form that the patient filled out, based on the category selected. It will be shown next to the patient's information.
  • Treatment statuses include Active, Completed, Cancelled, and On Hold.
  • Doctors can review treatment start dates, patient details, clinic association, and current status.
  • Doctors can update or end treatment records as clinically appropriate.
7. Orders

The Orders module shows all medicine orders generated from prescriptions written by the doctor. Orders move from the doctor to the clinic, and then from the clinic to the integrated third-party pharmacy for fulfillment and delivery to the patient's address.

Figure 6: Orders – list of orders associated with the doctor’s prescriptions.

Within the Orders view, the doctor can:

  • Review order details, including order ID, order date, patient, and MRN.
  • See when an order was sent to the pharmacy and when it was printed or processed.
  • Access further details via the actions menu (for example, viewing the linked prescription).

Each order is linked to exactly one prescription. A prescription may contain multiple medicines, but a new order always requires a new prescription. Doctors can edit or cancel an order only while it is still pending and has not yet been sent to the pharmacy. Once sent, the order becomes read-only, and any change requires a new prescription and a new order.

8. Prescriptions

The Prescriptions module provides a complete list of prescriptions created by the doctor. It also includes information about refill status, remaining refills, and expiration dates.

Figure 7: Prescriptions – overview of patient prescriptions, statuses, and refills.

Prescriptions are created when the doctor writes a handwritten prescription and uploads an image of it into the system. Global Admin staff then transcribes the handwritten prescription into a structured digital form. The doctor can later view this structured prescription in the Prescriptions list.

Typical fields and indicators include:

  • Patient name and prescription number.
  • Date of prescription and prescription status (e.g., Pending, Uploaded).
  • Refill status, remaining refills, and next refill date.
  • Expiration date and timestamp of when the prescription was sent to the pharmacy.

Doctors can modify or cancel prescriptions only while they are still pending and before they are sent to the pharmacy. Once transmitted to the pharmacy, the prescription is locked from editing, and a new prescription is required for any change or additional order.

9. Messages

The Messages module enables secure one-to-one messaging between the doctor and their patients, as well as between the doctor and clinic staff. Messaging is strictly scoped to existing relationships and is not a general chat system.

Figure 8: Messages – secure one-to-one chat with patients and clinic staff.

Messaging rules include:

  • Doctors can only message patients who are assigned to them.
  • Doctors can only message staff in the clinics where they are currently working.
  • Conversations are strictly one-to-one; group chats are not supported.
  • The Messages screen provides a searchable list of conversations and a chat pane for each selected conversation.
10. Key Rules and Permissions

The following business rules govern how doctors interact with the system and other roles:

  • Doctors have their own login and access only to the doctor-facing portal.
  • Doctors can define global availability; clinics cannot modify availability directly.
  • Only doctors can manually create or adjust appointments; clinics and patients cannot.
  • A doctor can be attached to multiple clinics, but cannot be booked in more than one clinic at the same time.
  • Doctors can view but not edit the patient’s Get Started questionnaire responses.
  • Doctors can edit or end treatments, cancel appointments, and modify orders/prescriptions only while they are pending and not yet sent to the pharmacy.
  • Once an order or prescription has been sent to the pharmacy, it is locked from editing; any change requires a new prescription and new order.
  • Doctors can message only their assigned patients and staff of their associated clinics, and only in one-to-one conversations.

This manual covers the doctor-facing functionality only. Other roles, such as Global Admin, clinics, patients, and the integrated pharmacy, have separate workflows and permissions defined elsewhere.

Clinic Portal – User Manual

For Clinic Admins and Staff (Full Permissions)

Support Documentation
1. Introduction

This user manual explains how clinics use the Clinic Portal to manage patients, treatments, appointments, products, orders, and billing. It is written from the perspective of a Clinic Admin with full permissions. Individual staff roles may have a subset of these capabilities.

The platform is owned and operated by the Global Admin. Clinics onboard onto the platform, connect their payment accounts, and use the system to run their day-to-day operations. Patients interact only with the clinic-branded experience and never see the Global Admin.

2. Getting Around the Portal

After logging in, you land on the Clinic Dashboard. The left navigation menu stays visible on every screen and is grouped into sections: Clinic Analytics, Scheduling, People, Clinical, Products, Invoicing, Billing, Communication, Branding, and Integrations.

Figure 1 – Clinic Dashboard and main navigation

3. Scheduling

The Scheduling section allows the clinic to see provider calendars and manage provider availability.

3.1 Calendar

The Calendar shows appointments for clinic providers with clinic patients. Clinic staff can filter by provider and date range, and switch between grid and list views. Appointments are view-only from the clinic side; scheduling changes such as cancellation or rescheduling must be coordinated with the doctor.

Figure 3 – Clinic Calendar (view-only appointments)

3.2 Availability

Availability lists the time blocks when each provider is available to see patients. These blocks define the appointment slots that appear on the calendar. Clinic staff can create and modify availability on behalf of providers by using the Add Availability action, including start date, duration, and number of slots. Changes here affect all clinics associated with that provider because availability is global per doctor.

Figure 4 – Provider availability managed by the clinic

4. People – Staff

The Staff screen lists everyone working in the clinic—providers, customer support staff, clinic admins, and other roles. From here, you can add new staff members, update contact information, assign user types, and activate or deactivate accounts.

Figure 5 – Staff management

5. Clinical Workspace

The Clinical section is where clinics manage their patients and the associated care records. Because patients enter the system through the clinic’s own marketing, each clinic can only see its own patients and related data.

5.1 Patients

The Patients view shows all patients that belong to the clinic, including registration date, MRN, contact details, and counts of treatments, prescriptions, and orders. Use the action menu at the end of each row to open a detailed patient profile and review history.

Figure 6 – Clinic patient list

5.2 Treatments

Treatment lists all treatment records for clinic patients. Each row shows the treatment number, start date, patient, contact details, and treatment status (Active, Completed, Cancelled, On Hold). Clinic staff can update the status when a treatment is completed, paused, or discontinued.

Figure 7 – Treatments for clinic patients

5.3 Prescriptions

The Prescriptions screen surfaces all prescriptions created by doctors for clinic patients. You can see prescription status (such as Pending or Uploaded), refill information, and key dates. Clinic staff use this screen to review prescriptions before sending related orders to the pharmacy.

Figure 8 – Prescriptions for clinic patients

5.4 Orders

Orders represent prescription orders that will be sent to the integrated pharmacy. The Orders screen shows order ID, date, patient, MRN, and transmission status. Clinic staff can trigger sending an order to the pharmacy or resend it if required, as long as the underlying business rules allow it.

Figure 9 – Orders list and pharmacy transmission status

6. Products & Pricing

The Products section allows clinics to configure what they sell—treatment categories, packages, medicine pricing, coupons, and patient intake forms. These settings control both the patient experience and billing.

6.1 Categories

Categories represent high-level treatment offerings such as Ketamine Therapy, Life Coaching, or Urgent Care. Clinics can add, edit, or remove categories to match the services they provide.

Figure 10 – Treatment categories

6.2 Packages

Packages bundle treatments, appointments, and medicines over a defined period (for example, a 3-month or 6-month ketamine therapy program). Each package has its own price, duration, and included components. Clinics can create their own packages from scratch and control the pricing for each one.

Figure 11 – Treatment packages with clinic pricing

6.3 Drugs Catalog

The Drugs Catalog lists all medicines available from the integrated pharmacy. For each drug you can see the strength, dosage form, package size, whether it is a controlled substance, and three pricing fields:

• Wholesale Price – base price received from the pharmacy.

• Suggested Retail Price – price suggested by Global Admin as a guideline.

• Clinic Sale Price – the price actually charged to patients by this clinic (clinics can update if needed).

Clinics can adjust Suggested Retail Price and Clinic Sale Price to achieve their desired profit margin while remaining competitive.

Figure 12 – Drugs catalog and pricing controls

6.4 Coupons

Coupons allow clinics to run promotions and discounts. Each coupon has a code, a discount value (amount or percentage), and a list of packages it applies to. Patients enter the coupon code themselves during checkout, and the discount is automatically applied to eligible purchases.

Figure 13 – Coupon management

6.5 Forms (Patient Intake)

Forms are treatment-specific intake questionnaires that patients complete at the start of their journey after choosing a treatment type. Clinics can create new forms, edit existing ones, or deactivate forms. Each form can be associated with one or more products so that patients see the correct questions for their selected treatment.

Figure 14 – Intake forms for treatments

7. Invoicing – Patient Purchases

Whenever a patient purchases a package, treatment, or extra medicines, the system automatically generates an invoice in the Invoicing section. Clinic staff can review invoices, verify amounts, and access the full history of patient purchases.

Figure 15 – Automatically generated patient invoices

8. Billing – Clinic Obligations to Global Admin

The Billing section tracks the financial relationship between the clinic and Global Admin. This includes monthly platform fees and the cost of medicines dispensed to patients.

8.1 Bills

Bills are generated automatically on the Global Admin side and appear here for the clinic. Each bill shows the total amount, status (Paid or Pending), invoice date, and due date. Clinics cannot create bills; their only actions are to review and pay them.

Figure 16 – Bills issued by Global Admin

8.2 Bill Payments

Bill Payments shows the history of payments made against those bills, including payment method, amount, status, and date. This provides a clear audit trail of what has been paid and when.

Figure 17 – Bill payment history

8.3 Payment Methods

In Payment Methods, the clinic manages the cards used to pay Global Admin. Multiple cards can be stored, a default card can be set, and cards can be added or removed as needed.

Figure 18 – Cards used to pay Global Admin

9. Communication

The Messages feature enables secure one-to-one communication within the platform. Clinics can message:

• Doctors who are treating the clinic’s patients.

• Patients who belong to the clinic.

• Global Admin, for operational or billing questions.

Clinics cannot message other clinics and cannot create group chats; all conversations are strictly one-to-one.

Figure 19 – Messaging for doctors, patients, and Global Admin

10. Branding

Branding controls the look and feel of the clinic experience. Clinics can upload their logo, select primary and secondary colors, customize chart colors, and choose a font style. These settings ensure that the patient experience reflects the clinic’s own brand rather than the Global Admin.

Figure 20 – Branding customization

11. Integrations

The Integrations section connects the Clinic Portal with external systems such as the clinic’s website and payment gateway.

11.1 Website Embeds (WordPress)

For marketing and patient acquisition, clinics can embed the Getting Started module and Categories with Packages directly into their WordPress or other websites. The Integrations page provides code snippets that can be copied and pasted into website pages, allowing patients to start their journey from marketing landing pages while still being tied to the correct clinic.

Figure 21 – Website integration snippets

11.2 Square Payment Integration

Square is used as the payment processor for patient purchases. Each clinic links its own Square account by entering the Application ID, Access Token, and Location ID. Once configured, all patient payments for that clinic flow through its Square account, while the platform separately bills the clinic for software usage and medicine costs.

Figure 22 – Square integration settings

Global Admin Portal – Functional & User Guide (v1)

Global Admin Portal

Support Documentation
1. Introduction

1.1 Purpose

This document describes the Global Admin side of the platform: what it is, how it works, and how a Global Admin uses each screen to operate and govern the system. It covers both a conceptual model (roles, entities, and flows) and a practical user guide for each module.

1.2 Audience

The primary audience is the Global Admin Owner and Support Global Admins. Secondary readers include product managers, QA analysts, and engineers who need to understand expected behaviour from the Global Admin perspective.

1.3 Scope

This document covers the Global Admin Dashboard, Clinics, Clinical data views (Patients, Treatments, Prescriptions, Orders), Products (Categories, Packages, Drugs Catalog, Forms), Invoicing (Payment Dashboard, Invoices, Invoice Payments), and Admin & Support (User Management, Messages, Tickets, Activity Log). The Analytics module is planned for a future phase and is intentionally excluded.

2. System Overview

2.1 Key Actors

  • Global Admin Owner – owns the platform and has full control. Can create and manage Support Global Admins and governs overall configuration.
  • Support Global Admin – operates the system day-to-day under limits defined by the Owner. Typically manages clinics, providers, orders, billing, and tickets.
  • Clinic Admin / Clinic Staff – work on the clinic portal; bring patients into the system via marketing campaigns and manage their own patients, appointments, and payments to Global Admin.
  • Providers / Doctors – medical professionals managed centrally by Global Admin. A provider can be attached to multiple clinics with separate availability per clinic.
  • Patients – individuals receiving treatment. They interact with clinics and providers, not with Global Admin or pharmacy directly.
  • Pharmacy (3rd party) – integrated only with Global Admin. Supplies the base drug catalog and prices and fulfills orders that clinics trigger via the system.

2.2 Business Model

Global Admin onboards clinics and provides them with three pillars: a virtual clinic platform, access to qualified providers, and an integrated pharmacy. Clinics then acquire patients through their own marketing channels and run their operations on top of this infrastructure. In the current model clinics pay Global Admin based on appointments and orders generated through the platform.

2.3 High-Level Flows

  • Clinic Onboarding – Global Admin creates a clinic record, sets up contact and billing details, and enables the clinic. Clinic-side users are created so they can start onboarding patients.
  • Provider Assignment – Global Admin creates providers and associates them with one or more clinics through availability schedules. Clinics then book appointments against this availability.
  • Patient Journey – patients arrive through a clinic’s marketing funnel, select a treatment, complete an intake form, are evaluated by a provider, receive prescriptions, and generate pharmacy orders.
  • Billing – the system tracks appointments and orders per clinic, generates invoices, and records payments made by clinics to Global Admin.
  • Support – clinics and providers communicate with Global Admin via messages and tickets. Global Admin monitors key activities via the Activity Log.
3. Data Model & Permissions

3.1 Main Entities

  • Clinic – represents a customer facility. Stores name, address, contact details, billing email and status (Active/Inactive). Linked to patients, treatments, prescriptions, orders, invoices, and payments.
  • Provider – doctor or other clinician managed by Global Admin. Can be attached to multiple clinics via availability. Has their own provider-portal credentials.
  • Patient – belongs to a clinic and participates in treatments, prescriptions, and orders.
  • Treatment – a program/package assigned to a patient (for example a 3-month or 6-month course). Has status such as Active, Completed, Cancelled, or On Hold.
  • Prescription – created by a provider. Drives pharmacy orders and may include refill information.
  • Order – represents a medication order to the pharmacy. Tracks status from created through sent, completed, or cancelled. Clinics and Global Admin can trigger Send to Pharmacy / Resend.
  • Product Category – a grouping of treatments/products such as Ketamine Therapy or Urgent Care.
  • Package – a treatment package with description, duration, and price. Global packages are visible to all clinics; clinics can customise their own pricing/variants.
  • Drug – item in the Drugs Catalog. Base list and prices come from pharmacy; Global Admin can adjust globally, and clinics can override clinic-level prices.
  • Form – intake or other questionnaire. Some forms are global templates; others are clinic-specific.
  • Invoice – billing record for a clinic based mainly on appointments and orders. Can be automatic or, rarely, manual/adjustment.
  • Payment – financial transaction applied to an invoice.
  • Ticket – support case raised by a clinic, provider, or Global Admin.
  • Activity Log Entry – record of significant actions such as login attempts, role changes, invoice creation, orders sent to pharmacy, and ticket updates.

3.2 Global Admin Roles

  • Global Admin Owner – unrestricted access to all configuration and data. Creates Support Global Admin accounts and defines operating policies.
  • Support Global Admin – operational administrator with broad but not absolute powers. Exact limitations are configurable but typically exclude owner-level tasks such as modifying core system defaults or elevating their own privileges.
4. Navigation Overview

The Global Admin portal uses a left-hand navigation menu containing the major modules:

  • Dashboard
  • Clinics
  • Clinical – Patients, Treatments, Prescriptions, Orders
  • Products – Categories, Packages, Drugs Catalog, Forms
  • Invoicing – Payment Dashboard, Invoices, Invoice Payments
  • Admin & Support – User Management, Messages, Tickets, Activity Log

The Analytics menu is presented in the UI but is part of a future phase and is not described here.

5. Dashboard

The Dashboard provides a high-level summary of platform activity: number of clinics, total active treatments, monthly revenue, and collection status. Bar and donut charts display trends such as monthly clinic revenue, collections versus outstanding balances, treatment categories, and active providers.

Figure 1 – Global Admin Dashboard

6. Clinics Module

The Clinics module lists all facilities onboarded on the platform and allows Global Admin to manage their basic details and operational status.

Figure 2 – Clinics list

Each row shows clinic name, address, phone, key contact emails, and status. Status has the following effects:

  • Active – clinic users can log in, onboard patients, and generate appointments and orders. Billing continues.
  • Inactive – clinic is effectively suspended, usually due to unpaid dues. Clinic users cannot log in and the system stops generating new invoices for that clinic.

Global Admin can add a clinic, edit details, and toggle Active/Inactive from the Actions menu. Billing rules are not configured per clinic as a subscription; instead, invoices are derived from that clinic’s appointments and orders.

7. Clinical Module (Global View)

The Clinical section provides cross-clinic visibility into patients, treatments, prescriptions, and orders. It is primarily an oversight and support tool for Global Admin.

7.1 Patients

Figure 3 – Patients (global view)

The Patients screen lists all patients in the system with registration date, MRN, contact details, counts of treatments/prescriptions/orders, and their home clinic. From here Global Admin can open a patient’s record for review but typically does not edit core demographics; changes are made by the clinic.

7.2 Treatments

Figure 4 – Treatments

The Treatments view shows treatment number, start date, patient, MRN, clinic, contact information, and treatment status. Global Admin can change a treatment’s status (for example to mark a course as Completed, Cancelled, or On Hold) when correcting data or resolving support issues.

7.3 Prescriptions

Figure 5 – Prescriptions

The Prescriptions screen lists all prescriptions with patient name, prescription number, dates, prescription and refill status, remaining refills, and expiry. Global Admin can modify prescription status and refill information where policy allows, for example when coordinating with the pharmacy or correcting provider errors.

7.4 Orders

Figure 6 – Orders

Orders represent medication orders to the pharmacy and show order ID, date, patient, MRN, clinic, and timestamps for when the order was sent or printed. Global Admin can update or delete orders and can trigger Send to Pharmacy or Resend just like clinics. Any changes propagate back to the clinic’s view so both sides stay in sync.

8. Products

The Products section defines the clinical and commercial catalogue that clinics draw from: treatment categories, packages, the shared drug catalog, and forms.

8.1 Categories

Figure 7 – Product Categories

Categories group treatments or offerings (for example Ketamine Therapy, Life Coaching, Urgent Care). Global Admin can add, edit, pause/resume, or delete categories. These are global definitions and are visible to all clinics.

8.2 Packages

Figure 8 – Packages

Packages represent concrete treatment bundles (e.g. Ketamine Therapy – 3 Months) with description, price, duration, and status. Global packages are visible to all clinics. Clinics can customise these packages for their own pricing and offers, but cloning a package as a separate object is not required in v1.

8.3 Drugs Catalog

Figure 9 – Drugs Catalog

The Drugs Catalog contains all medications available for ordering. Forms are intake and other questionnaires that patients complete when starting or continuing treatments. Global Admin can create, edit, and manage forms. Some forms are global templates shared across clinics, while others may be tied to specific clinics. Status indicators show whether a form is active or pending configuration.

9. Invoicing

The Invoicing section tracks financial relationships between clinics and Global Admin. Payments to pharmacy are handled outside the system in this phase; the portal focuses on what clinics owe and pay to Global Admin.

9.1 Payment Dashboard

Figure 11 – Payment Dashboard

The Payment Dashboard summarises total received, pending amounts, and number of successful payments for the selected date range. The list of recent payments shows which clinics have paid, via which method, and whether the payment completed. All metrics are aggregated across clinics.

9.2 Invoices

Figure 12 – Invoices

The Invoices screen lists invoices issued to clinics with facility name, total amount, status (Paid/Pending), invoice date, and due date. Invoices are generated mainly automatically based on a clinic’s appointments and orders, but Global Admin can occasionally create manual or adjustment invoices when necessary.

9.3 Invoice Payments

Figure 13 – Invoice Payments

Invoice Payments shows each payment a clinic has made: payment number, invoice, facility, amount, method, card last-4, status, and date. These payments are recorded when clinics pay through their portal using integrated card processing (Square).

10. Admin & Support

Admin & Support brings together tools for managing users, conversations, support tickets, and the system activity log.

10.1 User Management – Global Admin Users

Figure 14 – Global Admin Users

The Global Admin Users tab lists all Global Admin accounts with their contact details and status. The Owner can add new Support Global Admins, deactivate accounts, and update information. All Global Admins listed here log in through the Global Admin portal; there is no ability to impersonate clinic users in v1.

10.2 User Management – Providers

Figure 15 – Providers

The Providers tab lists all provider accounts (doctors and similar roles). Each provider can be attached to multiple clinics through separate availability schedules. These accounts are distinct from Global Admin users; their credentials are used on the provider portal.

10.3 Messages

Figure 16 – Messages

The Messages module provides one-to-one chat between Global Admin and other roles. Clinics and providers can initiate conversations with Global Admin; patients do not initiate chats in v1. All conversations appear in a single unified inbox today, with role-based filtering planned for a future release.

10.4 Tickets

Figure 17 – Tickets

Tickets are structured support requests. Clinics, providers, and Global Admin themselves can create tickets. Each ticket has a number, title, priority (for example High or Medium), status (Open, In Progress, Closed), creator, and timestamps. Anyone who raised a ticket can see its status changes. Priorities can be mapped to internal SLAs, even though enforcement is a process matter rather than an automated rule in v1.

11. Summary

The Global Admin portal forms the operational backbone of the platform. From this console the Owner and Support Global Admins onboard clinics, configure products, coordinate with the integrated pharmacy, and maintain billing and support workflows. Clinics remain in control of patient acquisition and day-to-day care delivery, while Global Admin ensures consistency, compliance, and financial integrity across the network.

As the product evolves, this document can serve as the foundation for future iterations: Analytics, more granular permissions, richer automation around billing and SLAs, and additional integrations. For now, it should provide a clear, end-to-end view of how the Global Admin role operates within the system.
